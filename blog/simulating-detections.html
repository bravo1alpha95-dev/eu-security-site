Simulating detections safely in the lab

You can confirm every EmpowerU Wazuh rule without running a real attack. File-integrity rules are triggered by harmless changes inside the lab agent container. Authentication and process rules are exercised by replaying synthetic log lines through wazuh-logtest. Everything here runs against the Docker lab or a manager you operate.

Defensive lab use only Run these steps only in the lab or on systems you own. The samples use the documentation address range 203.0.113.0/24 and placeholder names. Nothing here touches another system.

File integrity: rules 100020 and 100021

Wazuh uses different default rules for different file events. The EmpowerU rules are children of 550 (a file already in the baseline was modified). A brand-new file is 554 and does not match them.

Default IDMeaningMatches 100020 / 100021?
550Checksum changed: an existing file was modifiedYes
554File addedNo
553File deletedNo

From the lab/ directory, with the agent Active:

./fim-test.sh

The script makes two harmless changes in the agent container: it updates the timestamp of /usr/bin/ls (the program's contents do not change) and appends a comment line to /etc/ssh/sshd_config. If sshd_config does not exist yet, it creates it and waits for a scan first, so the later change is a 550 event.

Authentication and process rules: wazuh-logtest

The repository's tests/samples/ folder holds synthetic log lines for each rule. Replay them through wazuh-logtest on the lab manager:

# from the repository root
docker exec -i wazuh-lab-manager /var/ossec/bin/wazuh-logtest < tests/samples/100013-ssh-root-success.log

# burst and "success after failures" samples must be one session: pipe the whole file
docker exec -i wazuh-lab-manager /var/ossec/bin/wazuh-logtest < tests/samples/session-100016-100017-invalid-user.log
  • 100010 / 100011: session-100010-100011-pam.log (eight PAM failures, then a PAM session opened).
  • 100016 / 100017: the two session-100016-100017-*.log files (invalid-user and failed-password bursts, then a success).
  • 100013: 100013-ssh-root-success.log.
  • 100002: the five 100002-*.log process-monitoring samples (nc, ncat, socat, python -m http, busybox).
  • 100012 / 100018: the off-hours rules use the manager's local clock, not the log timestamp. Set TZ on the manager so its local time is between 00:00 and 05:00 to see them fire.

wazuh-logtest on 4.14.10 does not run the file-integrity decoder, which is why the FIM rules are tested with real file changes instead. Results from the 2026-11-13 run are in docs/LOGTEST.md.

Reading the alerts

docker exec wazuh-lab-manager tail -n 20 /var/ossec/logs/alerts/alerts.json

Look for "rule":{"id":"1000...". The EmpowerU rule replaces its parent as the leaf alert, so you will usually see 100020 rather than 550 for the same event.
