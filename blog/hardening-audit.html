Running the hardening audit

scripts/hardening-audit.sh in eu-ec-detect-community checks a subset of common CIS-benchmark-style settings on a Linux system you own and prints one PASS, WARN, or FAIL line per finding. It never changes anything.

Read-only by design The audit has no apply mode and ignores CONFIRM. It only reads files and runs status queries: ufw status, firewall-cmd --state, nft list ruleset, and systemctl is-active / is-enabled. It is a subset of CIS items, not a full benchmark or a compliance attestation.

1. Run it

git clone https://github.com/bravo1alpha95-dev/eu-ec-detect-community.git
cd eu-ec-detect-community
sudo ./scripts/hardening-audit.sh

Run as root for complete results. Anything the audit cannot read, such as /etc/sudoers as a normal user, is reported as WARN rather than guessed.

2. Read the results

PASS  ssh        PermitRootLogin no
WARN  ssh        MaxAuthTries 6 (CIS recommends 4 or less)
WARN  sudo       1 NOPASSWD sudoers entries (passwordless sudo; review each one)
PASS  firewall   host firewall active: ufw
PASS  perms      no world-writable files (or non-sticky world-writable dirs) in ...
FAIL  auditd     auditd installed but not active
# Summary: PASS=... WARN=... FAIL=...

This is an illustrative excerpt, not output from a real host.

AreaWhat is checked
SSHPermitRootLogin, PasswordAuthentication, Protocol, MaxAuthTries. Follows Include files and sshd's first-value-wins rule; Match blocks are not evaluated.
sudoNOPASSWD entries in /etc/sudoers and /etc/sudoers.d/
Firewallufw active, firewalld running, or an nftables input hook
PermissionsWorld-writable files, and world-writable directories without the sticky bit, in /etc and the system binary directories
Updatesunattended-upgrades (Debian/Ubuntu) or dnf-automatic (Fedora/RHEL family)
auditdService active
Password agingPASS_MAX_DAYS ≤ 365, PASS_MIN_DAYS ≥ 1, PASS_WARN_AGE ≥ 7 in /etc/login.defs

3. Find the report

The audit writes a redacted text report and a JSON summary with pass, warn, and fail counts to reports/ (directory mode 700, files 600, written under umask 077) only after it finishes. Review the report before you share it.

Options

VariableEffect
EU_AUDIT_NO_REPORT=yesPrint findings only; write nothing
EU_AUDIT_FAIL_ON=failExit 2 when any FAIL is found, for cron or CI
EU_AUDIT_ROOT=/mnt/imageAudit the files of a mounted image instead of /; live firewall and service checks are skipped
EU_AUDIT_MAX_LIST=20Maximum world-writable paths listed in the report

The full PASS / WARN / FAIL criteria are in the repository README.

Exit codes: 0 audit completed, 2 FAIL findings with EU_AUDIT_FAIL_ON=fail, 3 operational error (no report published).

Fixing findings

The audit does not fix anything. Make changes under your own change control, then re-run it. For SSH, confirm the effective settings with sudo sshd -T before and after, and keep a second session open while you change sshd_config so you cannot lock yourself out.
