Using the EmpowerU Sigma rules

Every EmpowerU Wazuh rule now has a Sigma port in eu-wazuh-detections/sigma/. Sigma is a vendor-neutral rule format, so the same detections can be converted to Splunk, Elasticsearch, and other SIEMs with sigma-cli.

Experimental All Sigma rules are status: experimental. They were linted and test-converted to Splunk, ES|QL, and Lucene, but not run against live Splunk or Elasticsearch data. The original Wazuh rules are the ones verified on Wazuh 4.14.10.

1. Install sigma-cli

git clone https://github.com/bravo1alpha95-dev/eu-wazuh-detections.git
cd eu-wazuh-detections
python3 -m venv .venv-sigma && . .venv-sigma/bin/activate
pip install -r sigma/requirements.txt

The requirements file pins sigma-cli 3.1.0, pySigma 1.5.1, and the Splunk and Elasticsearch backends, the same versions CI uses.

2. Lint

sigma check sigma/rules

3. Convert

python3 sigma/tests/convert_all.py --print splunk-raw   # Splunk, raw syslog in _raw
python3 sigma/tests/convert_all.py --print esql         # Elasticsearch ES|QL
python3 sigma/tests/convert_all.py --print lucene       # Lucene (no correlation rules)

The helper script converts base rules before the correlation rules that use them. pySigma 1.5.1 needs that order, and plain sigma convert loads files in filesystem order, which varies between machines. Single non-correlation rules convert fine with sigma convert -t splunk --without-pipeline sigma/rules/<file>.yml.

What maps to what

WazuhSigma typeNote
100002process_creationProcess-creation events instead of Wazuh process monitoring
100010, 100016event_count correlation8 failures in 180 s (PAM) or 120 s (SSH) from one source
100011, 100017temporal correlationBroader than Wazuh: any failure plus a success in 180 s
100012, 100018linux auth / sshdSigma has no time-of-day condition; apply the 00:00–05:00 window in your SIEM
100013linux sshdRoot SSH login
100020, 100021file_changeModified files only, like Wazuh 550 (not 554 "added")

The full table, with one Sigma file per Wazuh ID, is in sigma/README.md.

Field names

Linux syslog has no standard Sigma fields, so the auth and SSH rules match the raw line in a field called message (the Elastic Common Schema name) and group by host, rhost, or src_ip. The included pipeline sigma/pipelines/splunk_linux_raw.yml maps message to _raw and src_ip to src for Splunk. For other schemas, write a small pySigma processing pipeline.

Before production

  • Map field names to your data and test on your own logs.
  • Add the off-hours filter for 100012 and 100018.
  • Pair 100011 and 100017 with the burst rules if you want Wazuh's "eight failures first" behavior.
