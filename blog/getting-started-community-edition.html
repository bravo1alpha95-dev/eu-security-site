Getting started with the community edition

eu-ec-detect-community is a Bash toolkit that collects access evidence on Linux systems you own: users with login shells, recent and failed logins, SSH and sudo configuration excerpts, listening sockets, and auth-log excerpts. It is read-only by default and redacts secrets before anything is written.

What you need

  • A Linux host you own and are authorized to inspect.
  • Bash, GNU sed, and the usual coreutils. ss is used for the listener checks.
  • Git, to clone the repository.

1. Clone and configure

git clone https://github.com/bravo1alpha95-dev/eu-ec-detect-community.git
cd eu-ec-detect-community
cp .env.example .env && chmod 600 .env

Open .env and set EU_SCOPE_CIDR to the authorized range of systems you own. The 192.0.2.0/24 value in .env.example is only a placeholder. The file is parsed as plain KEY=value data and is never sourced as a shell script, so values are limited to a safe character set.

Then fill in scope/inventory.md with the hosts you own and the Rules of Engagement template scope/roe.md. Collection does not need an authorized ROE; only the apply script does.

2. Run the one-command path

./scripts/easy-run.sh

This runs preflight, a full read-only evidence collection, and a short summary. Nothing on the host is changed. Output goes to reports/, which is created with mode 700; every report file is mode 600. Each run writes a timestamped text report and a small JSON summary.

Review before you share Redaction covers common secrets, tokens, IP addresses, and email addresses, but it is best-effort. Read the report before you send it anywhere, and never paste unreviewed evidence into a public issue.

3. Watch for new listeners

./scripts/anomaly-checks.sh

The first run saves a per-host listener baseline with a SHA-256 sidecar. Later runs compare against it. Exit codes: 0 no changes, 1 changes, 2 baseline integrity failure, 3 operational failure.

4. Check your hardening

The toolkit also has a read-only CIS-style audit. See Running the hardening audit.

About the apply script

scripts/20_apply.sh is dry-run scaffolding for a Wazuh agent. It changes nothing unless you set CONFIRM=yes and scope/roe.md has Status: AUTHORIZED with every field filled. Even then it only writes a local config stub and prints install commands for you to run after verifying vendor packages yourself.

Run the checks yourself

for script in scripts/*.sh; do bash -n "$script" || exit; done
shellcheck -x scripts/*.sh
python3 tests/test_regressions.py
python3 tests/test_community_hygiene.py
python3 tests/test_hardening_audit.py

GitHub Actions runs the same checks on every push and pull request.
